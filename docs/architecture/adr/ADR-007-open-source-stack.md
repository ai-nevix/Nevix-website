# ADR-007 — Open-source, self-hostable stack

**Status:** Accepted
**Date:** 2026-09-17
**Specification reference:** §11 (technical stack), instruction §5, §13

## Context

The specification requires that the development and deployment stack be open source and
self-hostable, and that licences be verified at the exact version used rather than assumed:

> "'Open source' should be verified at the exact version used, not assumed."

The commercial motivation is reversibility rather than cost. For enterprise and public-sector
buyers — the stated target market — the ability to run the system on infrastructure they control
is frequently a procurement requirement, not a preference.

## Decision

Every component of the running system is open source and can be self-hosted:

| Layer | Choice | Licence |
| --- | --- | --- |
| Frontend | Next.js, React, Tailwind CSS, Radix UI | MIT |
| Animation | Framer Motion | MIT |
| Backend | FastAPI, Pydantic, SQLAlchemy, Alembic | MIT / BSD |
| Database | PostgreSQL (pgvector image) | PostgreSQL Licence |
| CMS | Strapi Community Edition | MIT (see caveat) |
| CI/CD | GitLab CE | MIT |

Docker, Nginx and the Prometheus/Grafana/Loki/GlitchTip monitoring stack were originally part of
this list but have since been removed from the project (see
[ADR-005](./ADR-005-docker-compose.md)); no replacement has been chosen yet, so the open-source,
self-hostable requirement above still constrains whatever is chosen next.

The full inventory, with pinned versions and the licence checked at that version, is in
[`docs/licenses/`](../../licenses/) and is regenerated by `npm run licenses:inventory`.

**No third-party SaaS is required to run the system.** There is no analytics vendor, no CDN
dependency, no hosted CMS, no error-tracking service and no font CDN — `next/font` downloads and
self-hosts the Manrope and Sora files at build time.

## Caveats recorded honestly

Two entries deserve more than a licence name:

**Strapi Community Edition (MIT).** The core is MIT. Some capabilities — SSO, audit logs,
publication workflows, content-type-level permissions — are Enterprise-only. Nothing this site
depends on is behind that line, but a future requirement for editorial approval workflows would
hit it. Noted so it is a known boundary rather than a surprise.

**Grafana and Loki (AGPL 3.0).** AGPL is a strong copyleft that extends to network use. It is not a
problem here because we operate them internally and do not offer them as a service to third
parties. It *would* become a consideration if NEVIX ever embedded Grafana in a client-facing
product, which is exactly the kind of thing that is expensive to discover late.

## Alternatives considered

**Best-of-breed managed services** — Vercel, Contentful, Datadog, Auth0. Faster to stand up and
better operated than we will operate them. Rejected because it contradicts the specification's
explicit requirement, and because it would make "can this run in our environment?" an answer of
"no" during procurement.

**Fully permissive-only (no AGPL)** — would rule out Grafana and Loki. Rejected as over-cautious
for internal tooling, with the boundary documented above instead.

## Consequences

**Good.** The stack can be deployed into a client's own environment. Procurement questions about
data residency and vendor lock-in have straightforward answers. The whole system runs on a
developer's laptop.

**Costs.** Operational burden transfers to us: backups, upgrades, security patching and capacity
planning are ours. That is real work and is budgeted in the runbook rather than discovered.

**Obligation.** The licence inventory must be regenerated when dependencies change. A dependency
that relicenses — which happens — is a decision point, not a routine upgrade.

## Revisit when

A capability has no adequate open-source equivalent. The response is not to abandon the position
but to isolate the proprietary component behind an interface we control and document the exception
in the licence inventory, so the boundary stays visible.
